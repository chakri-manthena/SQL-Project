# Beyond the Test Cases

This folder is the isolated research implementation for *Beyond the Test Cases: Evaluating the Robustness of LLM-Based Repair for Student SQL Queries*. The existing React/Express application remains the student exercise runner; it is not the experiment environment and its SQLite data must not be used to claim benchmark results.

## Current Implementation

- The pinned benchmark source is downloaded locally under the ignored `data/raw/SQLRepair/` path at commit `1566aea64f695213538f210405effbf198a1b10e`.
- Implemented: benchmark parsing, Level 1/2 evaluators, inferred schema/database builder, E_all/E_clean preparation, 99-slot independent variants, R1–R6 token rules, LLM pilot/full-run harness, candidate-targeted stress tests, validation, RQ1/RQ2 aggregation, RQ3 minimality/annotation, RQ4 rename/paired analysis, Tables 1–8, and Figures 1–3.
- The database-backed evaluation and LLM/model runs have not been executed in this workspace. The same-validator Java/Z3 SQLRepair adapter and final release verification remain incomplete; generated result files stay explicitly unavailable until a run produces them.

## Environment

Use Python 3.11 and Docker Desktop with Linux containers. From this directory:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item config.example.yaml config.yaml
$env:MYSQL_ROOT_PASSWORD = "choose-a-local-root-password"
$env:MYSQL_JUDGE_PASSWORD = "choose-a-local-readonly-password"
docker compose up -d
python -m unittest discover -s tests -v
```

The MySQL data directory is a named volume. `lower_case_table_names=1` is an initialization-time setting; if the server was initialized without it, rebuild the volume only when its data is disposable. The SQL mode intentionally omits `ONLY_FULL_GROUP_BY`.

## Core Run

Run these commands from `research/` after activating the environment above:

```powershell
python src/mysql_database.py --reset
python src/prepare_dataset.py
python src/build_variant_suite.py
python src/run_rules.py
python src/sqlrepair_baseline.py
```

The database builder recreates the study tables, checks the expected INSERT totals and all 41 table names, writes `data/processed/problems.json`, and verifies every reference with Level 1 as the SELECT-only `judge` account. `--reset` drops tables only from the dedicated research schema. Dataset preparation refuses to continue if any Fall 2020 original flag disagrees with Level 1. The variant builder reads problem metadata and submissions only; it does not read candidate files.

Configure the exact model identities, API-compatible endpoints, inference details, data-retention settings, and cost estimates in `config.yaml` before making any calls. Keep API keys in environment variables only. The open-weight model must be served at its configured endpoint. Run and validate the fixed pilot before any full model run:

```powershell
python src/llm_repairs.py --pilot
python src/run_validation.py --pilot
python src/analyze_results.py --pilot
```

The two-model pilot freezes a prompt-template hash in `logs/llm/prompt.sha256`. Afterward, run the full experiment and core report:

```powershell
python src/llm_repairs.py --full
python src/run_validation.py
python src/analyze_results.py
```

`analyze_results.py` writes `outputs/results.md` and the three SVG figures under `outputs/figures/`. Table 8 uses token pricing in `config.yaml` when supplied; otherwise actual dollar cost is reported as unavailable. LLM call logs provide latency and token totals.

After the core run is complete, generate RQ3 metrics and the annotation sample, then complete two independent annotation CSVs (`group_id,annotation`) using `rq3_annotation_guide.md`:

```powershell
python src/minimality.py
python src/minimality.py --annotator-1 outputs/annotations/annotator1.csv --annotator-2 outputs/annotations/annotator2.csv
```

The two annotation CSVs must each have columns `group_id,annotation`, with labels `preserves_student_approach`, `partially_changes_approach`, or `reproduces_reference_approach`. The sample is generated by the script; annotations must be completed independently by two human annotators.

For RQ4, prepare renamed schemas and variants, rerun both LLMs on E_clean, validate them, and analyze paired outcomes:

```powershell
python src/prepare_renaming.py
python src/llm_repairs.py --full --renamed
python src/run_validation.py --renamed
python src/analyze_renaming.py
```

Repair outputs and logs are ignored by Git because they contain benchmark-derived data. Confirm SQLRepair data reuse terms before distributing them.
